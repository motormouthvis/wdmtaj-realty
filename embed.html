Production embed guide

Add the School Rating Explorer widget to your listing or neighborhood pages. It shows nearby school ratings scoped to the page's address, which it scrapes automatically.

This guide page itself loads the popup embed — look for the floating School Rating Explorer button in the corner.

The snippet

Popup (floating bubble) — site-wide

Add this once, anywhere on the page (shared <head> or before </body>):

<script src="https://app.dreamneighborhood.com/explorer/sdk.js"></script>

This one tag is the whole popup install. It resolves the site's subscription and shows either the Neighborhood Explorer or the School Rating Explorer — when the site isn't entitled to the Neighborhood Explorer it loads the Schools widget for you, so there is no second popup snippet to paste. Add it once wherever your site keeps site-wide markup — the theme header or footer, the shared IDX template, or a tag manager — and every listing page serves it automatically.

On this production-test site: the popup tag is https://app.dreamneighborhood.com/explorer/sdk.js on every page, matching bills-fp-realty-co. The four featured embed pages also load an inline School Explorer or Neighborhood Explorer. Snippets never point at staging.

Inline School Rating Explorer

Add a container before the script:

<div id="dream-schools-explorer"></div>
<script src="https://www.dreamneighborhoodschools.com/embed.js" async></script>

The inline container is auto-detected via #dream-schools-explorer, .dream-schools-explorer, or [data-dream-schools-explorer].

Inline Neighborhood Explorer

Same idea, with the Neighborhood Explorer's own container and script:

<div id="dn-explorer"></div>
<script src="https://app.dreamneighborhood.com/explorer/inline.js" async></script>
Popup vs inline: the SDK self-detects. If it finds an inline container anywhere on the page it mounts inline; otherwise it shows the popup bubble. A page is therefore either popup or inline — adding an inline container turns off the floating bubble on that page. Use the popup site-wide and the inline embed on the specific pages where you want the explorer rendered in the layout.

How it works

  1. Resolves per-host config from GET /api/embed/config?host=… (unregistered hosts get a permissive enabled:true default).
  2. Best-effort scrapes the page address (order below).
  3. Posts {page_url, page_title, page_address} to POST /api/embed/scrape (validate + server-side geocode → {address, lat, lon}).
  4. Opens the explorer iframe at /embed scoped to that address.

All endpoints are on https://www.dreamneighborhoodschools.com (CORS / iframe enabled), so the widget works from any host over https.

Address scraping order

  1. document.title (e.g. 123 Main St, City, ST 12345)
  2. Structured data: JSON-LD PostalAddress, then og: address meta, then itemprop microdata
  3. Visible body text — only when data-search-page-content="true"
  4. Page footer (<footer> / [class*="footer"])
  5. URL slug (e.g. …/123-main-st-city-st-12345)
  6. Neighborhood / city from title or URL (resolved server-side)
  7. The host's configured default address (set in the admin)
  8. Manual entry inside the explorer

Because document.title is checked first, the most reliable thing you can do is put the full address in the page title. This demo isolates each path — see the test index.

Optional data-* overrides

Set these on the <script> tag (popup) or the inline container.

AttributePurpose
data-partner-idPartner identifier
data-widget-numberWhich configured widget to load (default 1)
data-accent-colorAccent color, e.g. #1fa55f
data-positionBubble side: left or right (popup)
data-bottom-offsetExtra bottom offset in px (popup)
data-tooltip-messageBubble tooltip text; supports {{address}}
data-require-addresstrue to hide the popup when no address resolves
data-search-page-contenttrue to allow scraping visible body text
data-suppress-on-inlinetrue to hide the popup when an inline embed is present
data-min-heightInline iframe min-height in px
data-show-headertrue to show the explorer header inline
data-addressHard-code the address (skips scraping)
data-lat / data-lngHard-code coordinates (skips geocoding)
data-api-baseOverride the API origin (advanced / testing)

Inline layout — most important rule

Put the inline embed in its own full-width section — not inside a content column or sidebar layout.

Do not place the inline snippet inside Bootstrap columns, sidebars, cards, fixed-width wrappers, or any parent with overflow: hidden.

<div class="container">
  <div class="row">
    <div class="col-lg-8">
      <h1>Neighborhood Name</h1>
      <div id="dream-schools-explorer"></div>  <!-- constrained — do not do this -->
      <script src="https://www.dreamneighborhoodschools.com/embed.js" async></script>
    </div>
    <div class="col-lg-4">Sidebar</div>
  </div>
</div>

Recommended layout (Bootstrap)

<div class="container pt-5">
  <h1>Georgetown</h1>
  <p class="lead">Neighborhood description...</p>
</div>

<div class="container-fluid px-0">
  <div id="dream-schools-explorer"></div>
  <script src="https://www.dreamneighborhoodschools.com/embed.js" async></script>
</div>

<div class="container pb-5">
  <p>More neighborhood details...</p>
</div>

Pages with a sidebar

Keep the sidebar with the page intro. Place the explorer in a separate full-width block below that row.

<div class="container pt-5">
  <div class="row">
    <div class="col-lg-8"><h1>Agent Name</h1><p class="lead">Bio...</p></div>
    <div class="col-lg-4">Contact card</div>
  </div>
</div>

<div class="container-fluid px-0">
  <div id="dream-schools-explorer"></div>
  <script src="https://www.dreamneighborhoodschools.com/embed.js" async></script>
</div>

Optional CSS

#dream-schools-explorer,
#dream-schools-explorer iframe {
  width: 100%;
  max-width: 100%;
  display: block;
}

CSS alone cannot fix a snippet placed inside a narrow column, and avoid width: 100vw; margin-left: -50vw; breakout hacks — fix the HTML layout first.

Pre-launch checklist

Inline snippet is not inside .col-* or a sidebar column☐
Inline snippet is in its own full-width block☐
No overflow: hidden on parents wrapping the explorer☐
Only one inline container per page☐
Address is present on the page for auto-detection☐
